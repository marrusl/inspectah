## 1. Problem

Each item names the bug, where it lives at `6e8a52b1`, and the evidence class. "Executed" means a throwaway integration test was run against HEAD and the observed output is quoted; "read from source" means the behaviour was traced but not run.

### 1.1 configtree writes the kernel snippet lists ungated

`write_config_tree` copies `config.files` entries gated on `disposition.is_included()` (`crates/pipeline/src/render/configtree.rs:212`), then rewrites `kernel_boot.modules_load_d`, `modprobe_d`, and `dracut_conf` with no gate at all (`configtree.rs:285-311`). The same file exists in both places on this host: `/etc/modules-load.d/driftify.conf` is a `config.files` entry (actionable, included) and a `ConfigSnippet` in `modules_load_d`.

**Executed against `6e8a52b1`.** `write_config_tree` on a snapshot whose `config.files` holds `/etc/modules-load.d/driftify.conf` with `disposition: excluded`: with `kernel_boot.modules_load_d` empty, `config/etc/modules-load.d/driftify.conf` is absent and the materialized roots are `[]`; with the same path present in `modules_load_d`, the file is present and the roots are `["etc"]`. A Configuration Files exclusion is silently overridden at export.

### 1.2 RPM-owned, unmodified modprobe.d files ship in every image

`collect_config_snippets` (`crates/collect/src/inspectors/kernelboot.rs:447-484`) reads every file in the directory and takes no `RpmState`. On this host `kernel_boot.modprobe_d` holds `firewalld-sysctls.conf` (owned by `firewalld`), `tuned.conf` (owned by `tuned`), and `driftify.conf`; `rpm_va` lists neither of the first two. The config inspector correctly left them out of `config.files`; the kernel inspector put them back, and item 1.1's ungated write ships them under `COPY config/etc/ /etc/`, overriding whatever the target base's own `firewalld` and `tuned` install. Read from source; the tarball listing confirms both files present.

### 1.4 The fcontext rule renders as a FIXME

`collect_fcontext_rules` (`crates/collect/src/inspectors/selinux.rs:318-345`) pushes each trimmed non-header line of `semanage fcontext -l -C` as a `String`. The snapshot holds one row with its column padding intact:

```
/srv/www(/.*)?                                     all files          system_u:object_r:httpd_sys_content_t:s0
```

The renderer (`containerfile.rs:1445-1462`) passes the row through `sanitize_shell_value`, whose regex rejects `( ) ? \s` among others (`crates/pipeline/src/render/safety.rs:11`), so every real rule fails and prints `# FIXME: fcontext rule contains unsafe characters: ...`, followed by `# RUN restorecon -Rv /`. ## 2. Settled decisions

Each paragraph records a decision made on 2026-10-26 and what it closes.

**EPEL and repo-enabling packages: mirror-safe order, availability proven.** A `@commandline` package whose name ends in `-release`, whose owned repo files and GPG keys are all present in the captured `repo_files` and `gpg_keys`, and whose name `dnf repoquery --available` on the source host lists from an enabled repo is repo-enabling, not repo-less, and the snapshot records which repo ids served it. It leaves the repo-less section: no MANUAL block, no upload prompt. At export the package stays repo-enabling only while at least one serving repo is still carried, included, and enabled with its key material; when the refinement drops the last serving definition the package is demoted back to the repo-less path with an unresolved instruction, never rendered as an active install by name (§ 3.3). Owning the repo definition is not the same as being installable from it: a `vendor-release` whose enabled repos carry only workloads, a definition that is disabled, or a mirror that omits bootstrap packages all own their files and are not available by name, so they keep the repo-less path and its upload control while their repo files are still copied (§ 3.3). The Containerfile copies the repo files and keys first, then runs `dnf install -y <name>` resolved from the copied repo. That works when the copied, enabled repo endpoints and their metadata are reachable from the builder with whatever credentials and CA trust they need; it does not create an offline mirror or rewrite a public metalink. The `dl.fedoraproject.org` permalink appears only as a commented alternative. A cosmetic `epel.repo.rpmnew` from installing after the COPY is accepted. CRB: when the host had a `codeready-builder-*` binary section enabled, that section's actual id is carried as `--enablerepo=<id>` on every `dnf` transaction the Containerfile emits, since the flag lasts one command (§ 3.3). `repo_providing_packages` is removed in the same bump. Genuine repo-less uploads keep the upload path with the staging bug fixed. Closes item 1.3 and the 2026-06-29 pre-spec's open question for this class.

**Package groups: exclude members; inert groups say so.** The group control is `SetInclude(Group)` over the group's effective members (present in `packages_added`, actionable, not locked). `GroupInfo` gains `effective_member_count` and `effective_included`; a group op whose effective members are all already in the requested state is refused with 422, never accepted with 200. A group with zero effective members shows no control and states why. Baseline-suppressed members stay in `members[]`, marked. Non-leaf members stay hidden by the leaf filter. Group render state is evaluated over the same effective set, before any display filter, so a group whose effective members are all excluded never renders `dnf group install` and a group with no effective members is inert rather than renderable (§ 3.7). Closes item 1.9.

**Kebab: hide in phase 1, header checkbox in phase 2, delete in phase 3.** Phase 1 hides the sidebar kebab menu with a prop that leaves the Ctrl+Shift+A/X chords working (they stay one release). Phase 2 moves bulk include/exclude onto a tri-state header checkbox on section lists and group rows. Phase 3 deletes the batch-toggle route, handlers, Sidebar code, confirm modal, and tests. The Kernel & Boot batch arm stops existing because `loaded_modules` becomes inventory. Closes item 1.13.

**Kernel & Boot: the `decision?` contract lands in phase 1; no remount.** `ContextItem` gains an optional `decision`, filled for sysctl and tuned rows now (their DTOs and `ItemId::Sysctl`/`ItemId::TunedSelection` already exist) and for config-backed rows once they carry dispositions. The three dead components and their tests are deleted. The data-model rule stands: a decision lives exactly once, on the entity the renderer reads. Kernel snippet lists leave `KernelBootSection`; every file under `/etc` is a `ConfigFileEntry` with one `ItemId::Config`; the ungated configtree write goes away; Kernel & Boot Customizations becomes a read-only projection over `config.files` by directory prefix. `tuned_custom_profiles` becomes a `ConfigCategory::Tuned` entry with `tuned_disposition` as the one activation decision. `sysctl_overrides` stays key-level, with `shadowed_by: Sysctl` recorded on the suppressed source entries by a finalization pass inside `collect()` that every scan path runs, and the shadowed entries refuse toggles in both directions (§ 3.5). The owner of a sysctl source file is decided by one criterion: the file is shadowed when the sysctl collection produced an override from it, whatever else in the kernel inspector failed; when the sysctl collection itself failed there is no override, no transformed decision, and no synthesized output, and plain config owns the file. `loaded_modules` becomes `FindingKind::Inventory` through the serde default and `ItemId::KernelModule` leaves the toggle vocabulary. `non_default_modules` is dropped. Closes items 1.1, 1.2, 1.7.

**The UI always reflects the export.** Every surface that shows a decision reads the state the export renders from, the projected session, and every op invalidates whatever stands between that state and the surface. The two server-lifetime caches of the reference projection are deleted, not keyed (§ 3.9). No cache or cache layer is added to satisfy this; the invariant is tested per surface (§ 8.15).

**No new section moves beyond the ones already planned.** The item moves this spec already contains stand: PAM and audit rows under Configuration Files, sysctl and tuned decisions surfacing in Kernel & Boot, `ungroup` into the expanded group row, the Unmanaged buttons becoming the header checkbox. Beyond those, the sidebar sections and their membership are unchanged in every phase: the `decision` contract on `ContextItem` makes rows decidable in place and does not recompute which sections are triage and which are reference. Where the interaction contract treats section kind as computed rather than declared, that is the direction, and a follow-up sections-reorganization spec owns it (§ 9). None of the round 1 fixes needed a new move.

**PAM and audit rules: the config walker owns them.** The two prefixes leave `CROSS_INSPECTOR_EXCLUDE_PREFIXES`; `/etc/pam.d/` gets `ConfigCategory::Pam`; `pam_configs`, `audit_rules`, the unconditional configtree write, and `CarryForwardFile` are deleted. They toggle through `ItemId::Config`, count in config stats, and appear in the audit report. authselect-managed symlinks are not local files. The SELinux reference section keeps a derived read-only pointer list. Closes item 1.8.

**Ruling: fcontext at build time.** `RUN semanage fcontext -a [-f <flag>] -t <type> '<spec>'`, `-s`/`-r` only when the user is not `system_u` or the level not `s0`; no `restorecon` line at all, because bootc labels the deployed tree from the image's own policy under `/etc/selinux` and ignores layer xattrs; `RUN semanage fcontext -a -e /srv /var/srv` emitted once before any `/srv` rule as a renderer-synthesized equivalence; collected equivalence rows render as `-a -e`; `Unlabel` renders with `'<<none>>'`; unrenderable rules print a two-line FIXME, instruction first. Replay is valid against the target policy, not only the source's, and against whatever local state the target already holds: each rule first checks that the target maps no equivalence on its exact spec (a same-subject equivalence is what `semanage fcontext -d` would delete, so such a rule is skipped with a FIXME in the build output and the equivalence survives, position 30), then deletes its own exact key from the target's local store (`-d`, which fails harmlessly on a key the source defines but the target never customized) and is then `-a`, falling back to `-m` when the key is stock policy, so the collected keys end the local list in source order whatever the target had; an equivalence is inspected on the target at build time, added when absent, left alone when identical, and a differing target mapping stops the build with an instruction rather than being overwritten; the collected and synthesized `/srv` equivalences are deduplicated and a conflicting pair is a FIXME; rules keep policy-store order; every host-supplied operand is single-quoted, equivalence operands must be absolute literal paths, and every build-time diagnostic is a static `printf` format with its operands passed as arguments, never interpolated into a double-quoted string (§ 3.1). The exported instructions say that data restored into `/var` keeps its old labels and needs `restorecon` before services start (§ 5.1). `file_contexts.local` leaves the config walk as derived policy-store state. Closes item 1.4.

**Ruling: backed `/var` directories are inventory; backing means created in the exported image.** Only unbacked directories change a Containerfile decision. A directory is backed when a tmpfiles.d entry creates exactly that directory (`d`, `D`, `v`, `q`, `Q` with the exact path), a unit directive names it, or an RPM owns it; `z`/`Z`/`e` and other attribute lines, file creators, and a parent's `d` line never back it, and the ancestor walk is deleted rather than narrowed. Backing is evaluated twice: at collection against the source host, recording provenance (`conf`, `line`, `unit`, `package`), and at export against what the refined export carries, so a creator that is excluded, runtime-only (`/run/tmpfiles.d`), or owned by a package outside the known target base and the exported install set yields a provisioning advisory and the generated `d` line, never a quietly retained backed verdict. A creator the export cannot place at all, an unowned `/usr/lib/tmpfiles.d` fragment or an excluded provider with no baseline to check against, is an explicit unresolved outcome: an advisory row in the view and a FIXME in the Containerfile, never a carried verdict and never a silent `d` line (§ 3.4). Backed ones collapse to a count; only `Unbacked` (plus non-root ownership or non-default mode) reach the view as rows. Closes items 1.6 and 1.12.

**Ruling: `EPEL_10_Everything_x86_64` is inspectah's bug.** The relabeling is `normalize_source_repos`, not host data; `from_repo` is whatever dnf saw at install time and inspectah displays it rather than improving it. The `RepoIndex` case split, the other half of the same item, closes by keying `RepoIndex` on a case-insensitive `RepoId` (§ 3.2). Closes item 1.5.

**Interaction model.** The critique's minimum consistent model and the interaction contract are the frontend default. One repo component replaces `RepoBar` plus `RepoGroupHeader` in single-host mode; `verified` and `incomplete` both get the control and `validate_target` accepts `Incomplete`; `unknown`, `disabled`, `stale`, and distro get state text and no control. A repo control acts on the repo's effective members, the projected, classified, actionable, unlocked packages attributed to it before any display filter; the server's no-op rule and the header's counts read that one set, and a repo with no effective member is refused in both directions and shows no control (§ 3.2). Server errors surface as a `role="alert"` toast carrying the server's `error` string after the optimistic revert. One upload modal; the server is the only matcher; the client checks `.rpm` only; rows key on the server's `matched`; an `uploaded` signal on `PackageEntry` survives reload. Snippet and PAM titles are the path under `/etc`. Storage drops `size_estimate` and `recommendation`. Closes items 1.10, 1.11, 1.14.

### Open positions

Positions this spec takes where the inputs disagreed or left a gap. Each is reversible without rereading the spec.

1. **Group include overrides the leaf default for its members.** "Install @Container Management" is explicit intent, and `containerfile.rs:597-604` already bypasses the leaf filter for any package whose include flag the user changed. Reverse: drop the bypass and a group include does nothing visible for non-leaf members.
2. **`Incomplete` is redefined; `Stale` takes its old meaning.** Today `Incomplete` means "referenced by packages, no section in any repo file". That is exactly the new `Stale`. `Incomplete` becomes "section exists and is enabled, but the build cannot fetch from it as captured" (no `baseurl`/`metalink`/`mirrorlist`, or a `gpgkey=file://` path not in `gpg_keys`). Reverse: delete `Stale` and keep `Incomplete` for both cases, at the cost of one state text for two causes.
3. **The repo-enabling file check is scoped to `/etc/yum.repos.d/` and `/etc/pki/rpm-gpg/`.** `epel-release` also owns `/usr/bin/crb`, a systemd preset, and licence files, which the capture never includes and the `dnf install` restores. Reverse: require every owned path, and no `-release` package ever qualifies.
4. **The recorded repo id lives inside `RepoAttribution`, not as a sibling `source_repo_recorded` field.** Every variant carries or implies it (`recorded()` accessor). Reverse: add the field and accept two writers for one fact.
5. **`in_base_image` is the baseline marker.** It is computed today as "absent from `packages_added`", which on an installed group means baseline-suppressed or base-image-only. The spec makes the computation explicit instead of adding a `baseline: true` twin. Reverse: add `baseline` and keep both.
6. **Sysctl-shadowed config entries become `Inventory` with `shadowed_by: Some(Sysctl)`.** The key-level override is the one decision; the file is a fact about where it came from. Reverse: keep them actionable and add a `Shadowed` refusal in `validate_target`.
7. **`advisory?` on `ContextItem` is adopted** (the contract left it unsettled). The Advisory label must come from a typed field, not subtitle text. Reverse: keep the subtitle string and accept that Storage advisories look unlike every other advisory.
8. **The collapsed `/var` summary row carries its list in `detail`.** `ContextItem` has no children; the expansion is the `<pre>` detail, one directory per line. Reverse: add a `children` array to `ContextItem` and teach `ContextList` to nest.
9. **`ConfigCategory::AuditRules` is not added; the existing `ConfigCategory::Audit` already classifies exactly `/etc/audit/rules.d/`** (`crates/collect/src/inspectors/config/classify.rs:20-23`). The decision text named a new variant; the code already has it under another name. Reverse: rename `Audit` to `AuditRules` in the same bump.
10. **`RepolessResolution` is replaced by `repo_enabling_from: Vec<RepoId>` on `PackageEntry`.** Of the three proposed variants, `Upload` is the default and `CommandlineAlternative` is out of scope. The round 1 draft kept one bit; the round 2 review showed the bit loses the fact export needs, which repo proved availability, so the field is the list of serving repo ids and "repo-enabling" means the list is non-empty. Reverse: keep the enum for the pre-spec's future variant, with the provider list inside its `Available` variant.
11. **An `Unparsed { raw }` variant on `FcontextRule`** keeps a line the parser rejected so the renderer can print it in the FIXME. Reverse: drop unparseable lines at collection with a warning and lose the raw text in the Containerfile.
12. **`-r` is the MLS range, not the role.** `semanage fcontext` has no role flag; the ruling's "`-s`/`-r` only when user is not `system_u` or level not `s0`" is read as `-s <user>` and `-r <level>` respectively.
13. **Carried from the interaction contract, with its labels:** mixed header state moves toward include-all (strong); coherent `list`/`listitem` markup on every row kind with native controls in the tab sequence (strong; the 2026-10-26 contract's `role="grid"` recommendation is withdrawn by its 2026-10-27 addendum, because the rows are not tabular and a grid reserves the arrow keys § 6.3 binds to expand and collapse); no Packages confirm modal in phase 2, an undo toast instead (moderate; assumes batch undo is one Ctrl+Z, which § 3.7 confirms); the `Inventory` label leaves `DecisionItem` in phase 3 (moderate). Reverse of the list choice: a full grid row/cell hierarchy for every row kind at once, with an entry protocol for child controls.
14. **Upload-dir rescan on session start** re-matches every staged `.rpm` through the same matcher the upload handler uses (`RpmFilename`, then name and arch with prefix shortening; never NEVRA filename equality, because staged files keep their real names under § 3.3) so `uploaded` survives a server restart, not only a browser reload. A file that matches nothing stays staged and unmarked; two files matching one package leave the later in filename order marked and the earlier staged, with a warning. Reverse: browser-reload survival only.
15. **The reference projection is computed from the live session; the two lifetime caches are deleted, not keyed.** `AppState.sections_cache` and `RefineSession::cached_reference` go. The projection is a few hundred rows of strings and `/api/snapshot/sections` is one GET per op, so a cache buys nothing measurable and a generation key is one more thing to invalidate on six paths. Reverse: keep both behind the session `generation` and invalidate on every mutation, undo, redo, reset, and resume.
16. **Repo-enabling availability reuses the collector's `dnf repoquery --available` call** (`repoless.rs:58-79`, already made for anaconda packages) rather than a per-repo query, with the query format widened to `%{name} %{reponame}` so one run names the serving repo of every available package. `None` (dnf failed) or a line the parser cannot split keeps the package repo-less. Reverse: `dnf repoquery --repo=<id> <name>` per candidate section, one dnf run per candidate.
17. **CRB enablement is per transaction, not a durable repo edit.** Every `RUN dnf ... install` the Containerfile emits carries `--enablerepo=<id>` for each enabled CRB binary section, with the id as the host wrote it. Reverse: one `RUN dnf config-manager --set-enabled <id>` after the repo COPY, which depends on `dnf-plugins-core` in the base and on the copied `.repo` file being the one the build resolves from.
18. **Add-or-modify is decided at build time**, per rule, as `-d` on the exact key, then `-a`, then `-m` on the same key, because the target policy store exists only in the build. Reverse: collect the full `semanage fcontext -l` on the source and render `-m` for any expression in the stock table; cheaper at build, wrong whenever the target base's stock policy differs from the source's.
19. **The ordered fcontext source is the policy store file; `semanage -l -C` is the fallback and is flagged.** Reverse: keep `-l -C` primary and accept that overlapping local rules may replay in the wrong order.
20. **Effective `/var` backing is computed at render time from the projected snapshot, not stored on the entry.** The snapshot keeps the source-host verdict and its provenance; the export reconciles against what it carries. Reverse: an `effective_backing` field written by the session on every projection, two writers for one fact.
21. **Staged uploads keep their real filename, which must pass one allowlist.** Export copies the verified file under that name and the Containerfile names it; `uploaded_version` says when it differs from the host's. Reverse: rename to the snapshot NEVRA, which mislabels a different version of the package as the one the host had.
22. **The sysctl shadowing criterion is "an override names the file as its source", not "the kernel inspector was not degraded".** The collector encodes a failed sysctl collection as an empty override list (`kernelboot.rs:91-98`), so a source path exists only when that collection succeeded; the finalization pass reads the list and nothing about the inspector's other failures. Reverse: a `sysctl_collected: bool` on `KernelBootSection`, one more field for a fact the list already carries.
23. **A collected fcontext key that already exists on the target is repositioned by delete-and-reinsert, not refused.** `-d` on the exact key is the operation `semanage` provides for that job and its two failure modes on a key (key absent, key stock-defined) are both harmless, whereas a refusal would need a build-time parser of the policy store inside a `RUN` line. The one case where `-d` mutates something other than a key, an equivalence with the same subject, is checked first and refused (position 30). The residual is stated in § 3.1 rule 1 and tested by B1. Reverse: refuse with a FIXME whenever a collected key preexists locally and overlaps another collected key, detected by an `awk` over `file_contexts.local` at build time.
24. **Equivalence equality is inspected on the target at build time.** `semanage fcontext -l -C` is the one policy-independent source of the target's local equivalences and its `subject = labeled_like` form needs no parser beyond field splitting. Reverse: render `-a -e` unconditionally and accept that `add_equal` refuses a duplicate with no way to tell identical from conflicting.
25. **A `/var` directory whose creator the export can neither place nor rule out is `Unresolved`, not provisioned.** Emitting a `d` line for a directory the base may already create duplicates a tmpfiles entry with captured ownership against the base's own; the unresolved outcome is visible in the view and the Containerfile and costs nothing when the user confirms. Reverse: provision every unknown case and accept duplicate-entry warnings at boot.
26. **A repo with no effective member is refused in both directions.** The repo control decides members and the `.repo` file follows them; a definition nobody installed from is decided where its file is decided. Reverse: let a zero-member repo op cascade to its file and keys as today, which gives the control two meanings.
27. **Uploaded filenames are allowlisted, not escaped per site.** One ASCII alphabet covers the Dockerfile parser, `COPY` globbing, shell-form `RUN`, and the comment context at once, including the commented-out pair that must stay valid when uncommented; escaping would need three mechanisms and still reject a newline. Reverse: quote every site first (the quoting skill's ordering rule) and then widen the alphabet, if a real vendor filename ever needs a byte outside it.
28. **A staged upload that fails export verification demotes the package, never the export.** The common cause is benign (directory cleaned, tarball moved, snapshot reopened elsewhere) and the demotion is visible as a FIXME and a response warning. Reverse: refuse the whole export on the first unverifiable upload.
29. **The member-based repo no-op rule and its first consumers are one release.** The rule refuses an op by the effective members' state; a control that still derives its state and direction from repo-exclusion history posts the refused direction whenever history and members disagree, and both disagreements are reachable through ordinary per-package decisions. Phase 0 therefore carries the counts-based Switch state and the requested-direction callback for the still-mounted `RepoBar` in both single-host and aggregate mode (§ 3.2, § 7). Reverse: keep the history-based `Repo` arm of `is_op_noop` one more release and ship the member-based rule with phase 1, which keeps the include-all-on-partial bug of § 3.2 live for that release.
30. **A collected label whose exact spec the target maps as an equivalence is refused, not repositioned.** `semanage fcontext -d <spec>` deletes a same-subject local equivalence before it looks for a label key, and ignores `-f` on that branch (SELinux 3.6 `seobject.py`, `fcontextRecords.__delete`), and no label-only deletion exists; the build checks the target's local equivalences for the exact subject first and skips that rule with a FIXME in the build output, leaving the equivalence and the remaining rules alone (§ 3.1 rule 1). Reverse: stop the build at the refused rule, as the differing-equivalence branch of rule 2 does, at the cost of hiding every later rule's result behind the first refusal.
31. **An uploaded package's export path has one writer, and a link where a cached RPM should be fails the export.** Step 2e never extracts a source-tarball payload for a package with `uploaded == true`, step 2f creates its destination with `O_EXCL`, and a `Symlink` or `Link` entry at an allowlisted `repoless-packages/` name for a non-uploaded package is a `TarballError` rather than a demotion, because the scanner writes cached RPMs as regular files and a link there is a crafted tarball, not a cleaned directory (§ 3.3). Reverse: demote the package and carry no member, which needs the extraction to report what it carried so the renderer can drop the `COPY`.

## 3. Design per item, types first

### 3.1 fcontext rules

```rust
// crates/core/src/types/selinux.rs

/// The `-f` flag of `semanage fcontext`; `All` emits no flag.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum FcontextFileType { All, RegularFile, Directory, CharDevice, BlockDevice, Socket, Symlink, NamedPipe }

impl FcontextFileType {
    /// `semanage fcontext -f` letter, or `None` for `All`.
    pub fn semanage_flag(self) -> Option<char> { /* f d c b s l p */ }
    /// Parses the `-l -C` type column ("all files", "regular file", ...).
    pub fn parse_column(text: &str) -> Option<Self>;
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct SelinuxContext {
    pub user: String,
    pub role: String,
    pub type_: String,
    /// MLS level, `None` when the policy prints no fourth field.
    pub level: Option<String>,
}

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[serde(tag = "kind", rename_all = "snake_case")]
pub enum FcontextRule {
    Label {
        spec: String,
        file_type: FcontextFileType,
        context: SelinuxContext,
        #[serde(default)]
        disposition: FindingKind,
    },
    /// `<<None>>` in the context column: do not relabel.
    Unlabel {
        spec: String,
        file_type: FcontextFileType,
        #[serde(default)]
        disposition: FindingKind,
    },
    /// `subject = labeled_like` in the equivalence section; renders as
    /// `semanage fcontext -a -e <labeled_like> <subject>`.
    Equivalence {
        subject: String,
        labeled_like: String,
        #[serde(default)]
        disposition: FindingKind,
    },
    /// A line the parser could not place. Display-only; the renderer prints
    /// it inside the FIXME so the operator can transcribe it.
    Unparsed { raw: String },
}
```

`SelinuxSection.fcontext_rules: Vec<FcontextRule>`, in collected order, plus `SelinuxSection.fcontext_source: FcontextSource` (`#[serde(default)]`, variants `PolicyStore`, `SemanageList`, default `SemanageList`) recording where the order came from. The three decision-bearing variants use bare `#[serde(default)]`: a collected rule is a customization the user made, and included-by-default is the intended contract, the same as `SelinuxPortLabel`. `Unparsed` has no disposition; `FindingKind` matching on it is the renderer's FIXME path.

**Collector** (`crates/collect/src/inspectors/selinux.rs:318-345`). Order is the first thing the collector has to preserve. `semanage fcontext -l -C` prints the local table sorted by expression, while the policy resolves overlapping local expressions by recency: a host that added `/srv/www(/.*)?` first and `/srv/.*` later labels `www` by the second rule, and a replay in sorted order labels it by the first. The ordered sources are the policy store files: `/etc/selinux/<policy>/contexts/files/file_contexts.local` holds `Label` and `Unlabel` rules in insertion order, `file_contexts.subs` holds local equivalences in insertion order (`file_contexts.subs_dist` is the distro's and is not collected). The collector reads those two files first, in file order, and sets `fcontext_source: PolicyStore`; it falls back to `chroot <root> semanage fcontext -l -C` only when neither file is readable, and then sets `SemanageList`, which makes the renderer print one caveat comment before the rules (§ 5.1). Formats: a `file_contexts.local` line is `regex [--|-d|-c|-b|-s|-l|-p] user:role:type[:level]`, whitespace-separated, `<<none>>` as the context for unlabel, the flag mapping onto `FcontextFileType` (`--` is `RegularFile`, no flag is `All`); a `file_contexts.subs` line is `subject labeled_like`. The `-l -C` output has two parts: lines before `SELinux Local fcontext Equivalence` are table rows split on a run of two or more spaces (column gaps are never a single space; path regexes can contain one), three columns giving `Label` (or `Unlabel` when the third is `<<None>>`, case-insensitive), the context split on `:` into user, role, type, and an optional level that may itself contain `:`; lines after the header match `^(\S+) = (\S+)$` and give `Equivalence { subject, labeled_like }`. Anything else non-blank and not a header becomes `Unparsed`. `file_contexts.local` leaves the config walk: add `/etc/selinux/*/contexts/files/file_contexts.local` and `file_contexts.subs` to the walker's exclusion globs (`walk.rs:128-130` already exclude the `contexts/files/*` family for unowned files; the `rpm_va` path at `config/mod.rs:150` needs the same skip, since the file is `rpm_owned_modified` on this host).

**Renderer** (`containerfile.rs:1445-1462`, SELinux block). Four rules make the replay valid against the target policy rather than the source's, and against the local customizations the target already carries. The renderer has no host access, so every decision that depends on target state is made by the emitted commands at build time:

1. **Delete the exact key, then add, then modify.** `semanage fcontext -a` refuses an expression and file-type key that is already defined, in the stock policy or locally (`fcontextRecords.__add` in policycoreutils 3.6, the version this host runs), so a source customization that overrides a stock expression cannot be replayed as a plain `-a`. `-m` on a key the target already holds locally is not an insertion either: libsemanage's local file database modifies the entry in place and flushes the list in its existing order, so a target that already had `/srv/.*` and then receives `/srv/www(/.*)?` followed by `/srv/.*` leaves the first as the later, winning local rule, the reverse of the source (SELinux 3.6 `fcontexts_local.c`, `database_llist.c`, `database_file.c`; local overlap resolves by recency, not specificity). Each rule therefore renders as three commands on one key, guarded by one check: `-d` is not scoped to label keys. `fcontextRecords.__delete` (SELinux 3.6 `seobject.py`) first asks whether the supplied spec is the subject of a local equivalence and, if so, removes that equivalence and returns, before any expression and file-type key is built, so `-f` does not reach that branch; a collected `Label` or `Unlabel` whose exact spec is a target equivalence subject (a source `/var/srv` label replayed onto a target carrying `/var/srv = /srv`) would delete the alias, then add the label, and every descendant would lose its equivalence. No label-only deletion exists in `semanage`. **Conservative narrowing (position 30):** before the `-d`, the emitted command reads the target's local equivalences, the same `semanage fcontext -l -C | awk '$2 == "="'` listing rule 2 reads, and compares the subject column with the spec; when the exact spec is a subject the rule is skipped without mutation, a FIXME naming the spec goes to the build output, and the remaining rules run; otherwise the triple runs as before. The comparison is `grep -qxF` on the subject column rather than `awk -v`, because a label spec is a regex that may contain a backslash, which `awk -v` escape-processes (POSIX assignment semantics), while rule 4 keeps backslash out of the equivalence operands rule 2 passes through `-v`. The spec is assigned once to a shell variable from a single-quoted literal and every later site reads `"$spec"`, which the shell expands as data and never re-parses. The form, with `<spec>` the single-quoted validated spec of rule 4:

   ```
   RUN spec='<spec>'; \
       eqs="$(semanage fcontext -l -C)" || { printf 'FIXME: could not list the target file contexts before replaying the rule for %s; fix semanage in the base, or exclude this rule, then rebuild\n' "$spec" >&2; exit 1; }; \
       if printf '%s\n' "$eqs" | awk '$2 == "=" { print $1 }' | grep -qxF -- "$spec"; then \
         printf 'FIXME: skipped the file context rule for %s; the target maps that path as an equivalence, which semanage fcontext -d would delete instead of a label; delete it with semanage fcontext -d -e, or exclude this rule, then rebuild\n' "$spec" >&2; \
       else semanage fcontext -d [-f <flag>] "$spec" 2>/dev/null || true; \
         semanage fcontext -a <args> "$spec" \
         || semanage fcontext -m <args> "$spec"; fi
   ```

   The `-d` removes the key from the target's local list when it is there and fails harmlessly when it is absent or stock-defined (`-d` refuses a key defined in policy); the `-a` then appends the key, so after the block the collected keys sit at the end of the local list in source order whatever the target held before; a stock key fails `-a` and `-m` adds the override under the same key; a key refused for any other reason (a type the target policy does not define, or a spec *under* a target equivalence subject, which `validate` in `seobject.py` refuses for `-a` and `-m` alike while its `-d` is harmless because that spec is not itself a subject) fails `-m` for the same reason and the build stops with semanage's message, which is the correct outcome. The refused-subject branch exits 0 so the remaining rules run; its FIXME is in the build log, not the Containerfile, because the renderer cannot know the target's equivalences, and the comment above the block says so. The listing is captured before the guard reads it, and a listing that fails stops the build with a FIXME, because without the capture a failed listing reads as "no equivalence" and falls through to the `-d` the listing could not vouch for; `set -o pipefail` is not POSIX, so the capture is the portable form. Rule 2 needs no capture: a listing that fails there leaves `$eq` empty and the branch runs `-a -e`, which `add_equal` refuses for an existing subject, so the build already stops on `semanage`'s own message. The `-d` is scoped to exactly the keys the source defines: nothing the source does not name is deleted or moved. What this does not preserve, stated plainly: a target-local key the source does *not* define that overlaps a collected key now loses to it, because the collected key is later; that is the meaning of replaying the source's customizations onto the target (position 23) and B1 (§ 8.14) measures it with a preseeded overlapping key.
2. **Equivalence dedup, conflict, and target equality.** The equivalence list is the collected `Equivalence` rows plus the synthesized `/var/srv = /srv` (below), keyed on `subject`. A collected row equal to the synthesized one is emitted once, as the collected row, and the audit report notes that the synthesis was redundant. Two rows with one `subject` and different `labeled_like`, or a collected row that maps the other direction (`/srv = /var/srv`), are a conflict: neither is emitted, and a two-line FIXME lists both and asks the operator to keep one. Each surviving row is then checked against the target at build time, because `add_equal` refuses any duplicate subject and `modify_equal` assigns the supplied substitute without comparing it (SELinux 3.6 `seobject.py`), so an `-a -e || -m -e` pair would silently replace a target mapping that differs. The emitted form reads the target's local equivalences once and branches on what it finds: absent, add; identical, do nothing; different, stop the build with the instruction (position 24):

   ```
   RUN eq="$(semanage fcontext -l -C | awk -v s='/var/srv' '$2 == "=" && $1 == s { print $3 }')"; \
       if [ -z "$eq" ]; then semanage fcontext -a -e '/srv' '/var/srv'; \
       elif [ "$eq" != '/srv' ]; then printf 'FIXME: %s is already equivalent to %s on the target, not %s; delete that equivalence with semanage fcontext -d -e, or exclude this rule, then rebuild\n' '/var/srv' "$eq" '/srv' >&2; exit 1; fi
   ```

   `$eq` is a shell variable in shell-form `RUN`; Dockerfile substitution does not apply to `RUN`. Both operands are the validated absolute literal paths of rule 4, so they are inert inside the single quotes and inside `awk -v` (backslash is not in the allowed set). The diagnostic is a static `printf` format the renderer writes with no host bytes in it; the operands reach it as separate arguments, the two literals single-quoted exactly as the `semanage` arguments are and `"$eq"` as a double-quoted expansion, which the shell never re-parses for substitution. Rule 4 allows backticks, `$`, and braces in an equivalence operand because single quotes make them inert; an earlier draft of this branch placed the same operands inside a double-quoted `echo`, where they are not inert and a subject such as `` /literal/`printf${IFS}X` `` ran `printf`, so the inert-operand property holds only while every site is a quoted argument, the diagnostic included (rule 4, last sentence). The `-m -e` form is never emitted.
3. **Order.** Rules render in collected order, which is policy-store order when `fcontext_source` is `PolicyStore`. For `SemanageList` the block starts with `# NOTE: rule order comes from a sorted listing, not insertion order; if two expressions overlap, reorder so the intended winner is last.`
4. **Quoting and operand validation.** Every host-supplied operand is single-quoted: `spec`, and both equivalence operands. Inside single quotes the only unsafe characters are `'`, `\n`, and NUL (containerfile-value-quoting skill). Equivalence operands are additionally required to be absolute literal path prefixes: they begin with `/`, contain no whitespace, and contain none of `* ? [ ] ( ) | \`, because `-e` takes a path, not a regex. A label `spec` must begin with `/`, as every `file_contexts` expression does; a spec that does not (`--help`, which `semanage fcontext -a` answers with its usage text and exit 0, skipping the rule silently) renders the FIXME. `type_`, `user`, and `level` are bare tokens and must match `^[A-Za-z0-9_.:-]+$`. A rule failing any check renders as the two-line FIXME of § 5.1 with the offending operand quoted in the second line, never as a command: `/tmp/$(id)` and `/srv;rm -rf /` reach the Containerfile only inside a `#` line. The synthesized constants are not host input and need no check. **Diagnostics are data.** A message the emitted commands print at build time never interpolates an operand into a double-quoted string: it is a static `printf` format, written by the renderer with no host bytes, and each operand is its own argument, single-quoted when it is a validated literal and `"$var"` when it is a shell variable holding target data or the spec; the alternative, a generic message that names only the rule's index, is acceptable where an operand has no safe quoted form. Rules 1 and 2 are the two diagnostic sites, and § 8.9 executes both with allowed shell-looking bytes.

The renderer walks included `Label`/`Unlabel` rules and, before the first whose `spec` begins with a var-symlinked top level, emits the equivalence once:

### 3.2 Repo attribution and `RepoIndex`

```rust
// crates/core/src/types/repo.rs

/// A yum repo section id. Equality, hashing, and ordering are ASCII
/// case-insensitive; `Display` keeps the id as the host wrote it.

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]

    /// `%{from_repo}` equals a section id on the host (case-insensitive).

    /// No section on the host matches (repo removed or renamed since install).
    Stale { recorded: String },
    Pseudo { which: PseudoRepo, recorded: String },
    Unrecorded,
}

/// One parsed `[section]` of a `.repo` file. Shared by collect and refine;
/// replaces `extract_section_ids` (source_repos.rs) and `parse_repo_sections`
/// (repo_index.rs), which parse the same INI two different ways today.
pub struct RepoSectionDef {
    pub id: RepoId,
    /// `enabled=` value, `true` when absent (dnf semantics).
    pub enabled: bool,
    pub has_source: bool,          // baseurl, metalink, or mirrorlist present
    pub gpg_key_paths: Vec<String>,
}
pub fn parse_repo_sections(content: &str) -> Vec<RepoSectionDef>;
```

`PackageEntry` gains `#[serde(default)] pub repo_attribution: RepoAttribution` (default `Unrecorded`). `source_repo: String` keeps its meaning for the forty-odd consumers: the resolved id for `Exact` and `Resolved`, the recorded value otherwise.

**Normalization rule** (`normalize_source_repos`): exact case-insensitive match against any section, enabled or not, wins first (`Exact`). Otherwise substring against sections with `enabled = true` only; exactly one match is `Resolved`, more than one is `Ambiguous` and `source_repo` is left as recorded. No match: `@commandline`, `anaconda`, `@System` are `Pseudo`; empty is `Unrecorded`; anything else is `Stale`. On this host `epel` matches `[epel]` exactly (A1) and the content-template sections never participate. The rule is order-independent by construction: it never iterates sections looking for a first hit. `Exact` is permitted to land on a section with `enabled = 0`: dnf recorded that id, so the packages keep the attribution, and the repo surfaces with provenance `Disabled` and its packages listed under it (§ 6.3). What `Exact` never does is relabel.

**`RepoIndex`** keys `packages_by_repo`, `repo_file_by_section`, `gpg_keys_by_section`, and `provenance_map` by `RepoId`, so `handlers.rs:209`'s `to_lowercase()` and the comment at `repo_index.rs:77-80` go away. `ItemId::Repo { path }` comparisons go through `RepoId`, which also closes the hole where the server accepted an id the view never emitted.

**Repo no-op and refusal.** `is_op_noop`'s `ItemId::Repo` arm (`session.rs:1806-1814`) stops reading `excluded_sections_at`: a history bit cannot say whether an op changes a member. The arm applies the `Group` rule of § 3.7 to the effective set: `SetInclude(Repo, include)` is `Err(NoopTarget("all <M> effective members of '<id>' are already included|excluded"))` (422) when every effective member already holds the requested state, and `Err(NoopTarget("nothing to decide in '<id>': <reason>"))` when the set is empty, where `<reason>` is `all <n> members are locked` or `no package is attributed to it`; otherwise the op records one timeline entry and cascades. Both directions skip locked members, which are also outside the counts. A per-package change after a repo op leaves `enabled` alone and moves `effective_included`, so a repo with one of two members excluded reads mixed, not checked, and include-all on it is a real op. **The guarantee a control can rely on:** for a repo with at least one effective member, the direction derived from the counts is never the refused one. A control that derives them from `enabled` can, in both directions (below).

**Classification** happens in `scan_dnf_cache_for_repoless` (`repoless.rs:99-192`) before the cache scan, and has two tests that must both pass. *Provides repository configuration:* a candidate with `source_repo == "@commandline"`, a name ending in `-release`, and an `rpm.file_ownership` entry whose paths under the two directories are a subset of `repo_files[].path ∪ gpg_keys[].path` (and at least one repo file among them). *Installable by name from a repository the export can carry:* the package name is a key of the map `get_available_packages` returns (`repoless.rs:58-79`; position 16), which lists what the host's enabled repos serve *and which repo serves it*. A package passing only the first keeps `repoless_annotation` (`No repo source: owns <n> captured repo file(s) but is not available from them`), keeps the upload control, and still has its repo files and keys copied, since those are `config.files` and `gpg_keys` decisions of their own. When `get_available_packages` returns `None` (dnf failed, or the host's dnf does not print the format) the second test cannot run and the package stays repo-less: the recovery path is suppressed only on proof. `rpm.repo_providing_packages` and its merge at `merge.rs:949` are deleted. On this host `epel-release` owns `epel.repo`, `epel-testing.repo`, `epel-cisco-openh264.repo`, and `RPM-GPG-KEY-EPEL-9`, all captured, and `[epel]` serves `epel-release`, so `repo_enabling_from = ["epel"]`.

**Render.** The install partition at `containerfile.rs:635-640` becomes `!pkg.repo_enabling_from.is_empty() || base.ends_with("-release")`. The block order is already mirror-safe (Custom Repositories, GPG Keys, then Repo-enabling packages). When no serving id survives, the package is demoted to the repo-less rendering, the upload control returns in the view (`repoless_annotation` is set on the projection: `No repo source: the repo that served <name> (<id>) is not carried by this export`), and the Containerfile prints `# FIXME: include <file> under Configuration Files, or re-include repo <id>, or upload the RPM; <name> installs from that repo definition, which this export does not carry` in place of any active install. **Conservative narrowing:** a demotion is the only outcome when proof is lost; the renderer never keeps an active `dnf install -y <name>` on the strength of a repo the export does not carry, and never substitutes another enabled repo that the host's query did not name as a provider. **CRB.** `--enablerepo` lasts for one `dnf` command (DNF command reference, options), so a flag on the bootstrap transaction does nothing for the group and package transactions that follow, and those are the ones whose EPEL dependencies can live only in CRB. The renderer collects `crb_ids: Vec<RepoId>` from `parse_repo_sections` over the included `repo_files`: every section with `enabled = true` whose id, lowercased, starts with `codeready-builder-` and contains neither `-debug-` nor `-source-`, kept as the host wrote it (`rhel-9-for-aarch64-appstream`-style mirrored ids are also fine; a noncanonical id is passed through, never rewritten). **The staged filename rule.** Staged files keep their real filename (position 21): a user who uploads `epel-release-9-12.el9.noarch.rpm` for a host that had `9-11.el9` has injected a newer package, and renaming it to the snapshot NEVRA would mislabel it. A real filename that reaches `COPY`, `RUN dnf localinstall`, `rm`, and a `#` comment is host input in four contexts at once, so the name is constrained once, not escaped per site (position 27). One function, `validate_staged_name(&str) -> Result<(), NameError>` in `crates/refine/src/rpm_filename.rs`, accepts a basename when, and only when: every byte is in `[A-Za-z0-9._+~^-]`, checked byte by byte with `u8::is_ascii_alphanumeric` (never `char::is_alphanumeric`, which admits Unicode); the first byte is `[A-Za-z0-9]` (no leading dot, no leading `-`, so no hidden file and no option injection); it ends in `.rpm` case-insensitively; and its length is 5 to `MAX_UPLOAD_FILENAME_LEN = 200` bytes. The alphabet is rpm's: Name is alnum plus `-._+`, Version and Release alnum plus `._+~^` (`^` for snapshot versions such as `1.2^20240101git1`), arch `[a-z0-9_]`, and vendor names use `_`. No allowed byte is significant to the Dockerfile parser (whitespace, `\` continuation, `$` substitution, a leading `[` for JSON form), to `COPY` globbing (`* ? [ \`), to shell-form `RUN` and the `&& rm` operand (no metacharacter, quote, or whitespace; `~` is never word-initial because every site prefixes `/tmp/` or `repoless-packages/`), or to a comment (`\n` and `\r` are rejected, so nothing can close it). The commented-out pair at `repoless.rs:59-61` stays valid when uncommented for the same reason. The parsed `version_release` is a substring of the validated name and inherits the alphabet. The rule is enforced at every entry point, and rejection is always rejection, never stripping: the upload handler on the raw multipart filename before anything else (400, nothing staged; `upload.rs:29-37` today strips with `Path::file_name` and `to_string_lossy`, which turns `../x.rpm` into `x.rpm` and admits `$(id)`); the rescan (skip and warn); and the export pre-pass below, because `cache_path` and `uploaded_version` deserialize from the snapshot (`rpm.rs:52-59`) and nothing there is trusted. At render, `uploaded_version` is re-derived from the verified basename through `RpmFilename::parse`, never read from the snapshot field; `pkg.name`, `pkg.arch`, and `host_version` reach the `# uploaded ...` comment through `sanitize_for_comment()`. The same validator gates the pre-existing dnf-cache path: `repoless_rpm_lines` builds that path's `COPY` source from snapshot NEVRA fields bare (`repoless.rs:29-30`, `:46-48`), the same injection class from a crafted snapshot, and from phase 0 a NEVRA filename that fails the rule renders the non-active FIXME instead of a `COPY`. That closes it in the same bump rather than § 9, because it is the same function on one more string.

**Upload staging** (`crates/web/src/upload.rs:17-78`, `session.rs:626-690`). The handler today reads the whole field with `field.bytes()` and writes it once (`upload.rs:45-54`), so a 500 MiB RPM costs a 500 MiB allocation before any matching runs; the earlier draft's "keeps streaming" was wrong. It also treats every multipart field as an RPM, defaults a missing filename to `unknown.rpm` (`:29-32`), which passes the suffix check, and reports only the last match (`:62`). Phase 0 changes the request contract and the staging mechanics together:

- **Field trust.** Exactly one field, named `file` (the client's `useRpmUpload.ts:113`), carrying a filename; a request with no such field, a second field, or a field without a filename is 400 before anything is staged. The filename passes `validate_staged_name` or the request is 400 with the rule named.
- **Chunked staging into a per-request part file.** The field is streamed with `field.chunk()` into `tempfile::Builder::new().prefix(".upload-").suffix(".part").rand_bytes(16).tempfile_in(upload_dir)` (`tempfile` is already a dependency of `crates/web`, `Cargo.toml:19`): opened `O_EXCL` with mode 0600, unique per request, and a `NamedTempFile` that deletes itself on `Drop`, including when axum drops the handler future on a client disconnect, so an abandoned 500 MiB transfer leaks nothing. Resident memory per upload is one multipart chunk. The part name never ends in `.rpm` and the filename rule bans a leading dot, so a part file and a staged name cannot collide and the rescan skips part files with no special case. A size overrun surfaces from `field.chunk()` as a `MultipartError`; the handler maps every `MultipartError` through its own `status()` (axum 0.8.9: a `DefaultBodyLimit` overrun arrives as `StreamReadFailed` wrapping `LengthLimitError`, which `status()` maps to 413 `PAYLOAD_TOO_LARGE`; malformed multipart is 400) instead of the blanket 400 at `upload.rs:24-28`, `:45-49`. The route limit at `lib.rs:110` becomes the named constant `UPLOAD_LIMIT_BYTES` (500 MiB); multipart framing counts against it, so the 413 test of § 8.2 exercises the route layer, which is said there.
- **`sync_all()` before the lock.** When the stream ends the part file is flushed to disk before the session mutex is taken, so the critical section below holds no I/O wait.
- **Startup sweep.** When a process first opens the upload directory, before the server listens, it removes regular files (by `symlink_metadata`) matching `.upload-*.part`, the leftovers of a process that died mid-transfer. A running server never removes a part file by name pattern; each request removes only its own, through `Drop`.
- **The upload directory is owned and private.** `ensure_upload_dir` (`session.rs:585-604`) derives `<stem>-uploads` beside the tarball and `create_dir_all` accepts whatever is there, including a symlink to a directory another local user pre-created. It now creates the directory with mode 0700 and, when it already exists, requires `symlink_metadata` to show a directory (not a symlink) owned by the effective uid with no group or other write bit; otherwise the session refuses to stage (`RefineError::TarballError` naming the path) and the upload returns 500. The canonical path of the directory is computed once here and kept on the session for the checks below.

The lifecycle, in order, with nothing on the package touched until the last step:

1. **Stage** to the part file, as above. Any failure drops the `NamedTempFile`, which removes it, and changes nothing.
2. **Match** with `RefineSession::match_uploaded_rpm(&filename) -> Option<UploadMatch>`, which is today's `mark_uploaded_rpm` matcher (`session.rs:626-687`: exact NEVRA first, then `RpmFilename` name and arch with progressively shorter name prefixes) with every mutation removed. `UploadMatch { canonical: String, match_kind: UploadMatchKind, host_version: String, uploaded_version: Option<String> }`; `UploadMatchKind { Exact, VersionDiffers }` serializes as `exact` | `version_differs`, `host_version` is `format!("{version}-{release}")` of the entry, and `uploaded_version` is `Some(parsed version-release)` when it differs from `host_version`. inspectah does not compare RPM versions, so the kind says the version differs and the row shows both; "newer" is the user's claim, not the server's. No match: the part file is persisted to `upload_dir.join(filename)` so it is staged for the modal's "remove it or try another", nothing on any package changes, and the response is `status: "unmatched"`.
3. **Place** under the real filename, and 4. **Record**, run inside one hold of the existing session mutex (`state.session.lock()`, the lock `upload.rs:51` already takes) with no `.await` inside it; the match of step 2 runs under the same hold so it cannot go stale. In order: the 409 check, then `NamedTempFile::persist(upload_dir.join(filename))`, an atomic `rename(2)` that replaces a same-named file, then `set_uploaded`, then deletion of a superseded file, then release. The 409 check comes before the rename and applies to unmatched placements too: if another package already has `cache_path == upload_dir.join(filename)` the upload is refused with 409 `<filename> is already staged for <other name.arch>` and the part file dropped; no rename ever replaces a file that is another package's `cache_path`. Replace policy: if the matched package already has `uploaded == true` with a different `cache_path`, the previous file is deleted after the record step; the same filename re-uploaded is replaced by the rename, which is the intended replace. **Overlapping uploads:** two requests for one filename, or one package, each stage their own part file and reach the critical section in some order; the one whose critical section runs last wins, both receive 200, and the generation bump tells the client which state holds. A request's failure drops only its own part file; the other request is unaffected. `RefineSession::set_uploaded(&canonical, staged_path, uploaded_version)` records the entry's current `(repoless_cached, cache_path, uploaded_version)` in `prior_cache: HashMap<String, PriorCache>` on the session when the entry was `repoless_cached` from the host's dnf cache and not yet `uploaded`, then sets `uploaded = true`, `repoless_cached = true`, `cache_path = Some(staged_path)`, `uploaded_version`, and calls `invalidate_caches()`. The record step is in-memory and cannot fail once the rename has succeeded, so the session never reports `uploaded` for a file that is not in place, and a failure anywhere before it leaves the previous upload and the package exactly as they were. The handler is split into `stage(field) -> StagedPart` and `commit(&mut session, StagedPart, &filename) -> UploadOutcome` so the tests of § 8.2 can interleave two uploads deterministically.

**Export.** `copy_uploaded_rpms` (`session.rs:3259-3295`) is confined today by construction, `read_dir(upload_dir)` plus a NEVRA allowlist, though it follows symlinks (`fs::copy(entry.path())`, `:3291`). Reading `cache_path` instead would lose that confinement, because `uploaded` and `cache_path` are snapshot fields a malformed or imported snapshot can set to any readable file. The replacement proves each file before it copies anything, in `verify_staged_upload(upload_dir_canon: &Path, pkg: &PackageEntry) -> Result<VerifiedUpload, Refusal>`, in this order: (1) `pkg.uploaded` is true, the package is included, and `cache_path` is `Some`; (2) `basename = Path::new(cache_path).file_name()` is valid UTF-8 and passes `validate_staged_name`; (3) `canonicalize(parent(cache_path)) == upload_dir_canon`, the parent only, since canonicalizing the full path would follow a final symlink; (4) `p = upload_dir_canon.join(basename)` and `symlink_metadata(p).file_type().is_file()`, which is false for a symlink; (5) the file is opened, the handle is `fstat`ed, and the handle must be a regular file with the same `(dev, ino)` as step 4 (`std::os::unix::fs::MetadataExt`, no new dependency), which closes the check-to-copy race on the final component; the copy then reads from that handle with `io::copy`. `VerifiedUpload { canonical: String, basename: String, uploaded_version: Option<String> }` carries the basename and the version re-derived from it. `render_refine_export` runs the verify-and-copy pass at its step 2f (`session.rs:3357-3362`), before the Containerfile is rendered at step 3, into `export/repoless-packages/<basename>`, and hands the resulting `VerifiedUploads` map (`name.arch` to `VerifiedUpload`) to the renderer through `render_ctx`; the Containerfile preview runs the same verification without the copy and passes the same map, so preview and export cannot disagree. `repoless_rpm_lines` (`crates/pipeline/src/render/repoless.rs:28-48`) names only what the map holds: `COPY repoless-packages/<basename> /tmp/`, `RUN dnf localinstall -y /tmp/<basename>`, `&& rm /tmp/<basename>`, and when `uploaded_version` is `Some` the comment `# uploaded <name>-<uploaded_version>.<arch>; the host had <host_version>` with the three snapshot-derived operands through `sanitize_for_comment()`. The `COPY`, `RUN`, `rm`, comment, and tarball member all read one value. **One writer per output path (position 31).** `export/repoless-packages/<basename>` has two possible writers today. Step 2e extracts the source tarball's `repoless-packages/` entries for every included `repoless_cached` package (`extract_payload_dirs_from_tarball`: allowlist at `session.rs:3185-3195`, extraction at `:3219-3245`, which recreates `Symlink` and `Link` entries as links), and step 2f copies the upload afterwards (`:3350-3362`). An uploaded package is `repoless_cached` too, so a crafted source tarball can place a symlink at the exact-NEVRA name and the copy at step 2f would open through it; `fs::copy` (`:3291`) follows and truncates whatever the destination names (`std::fs::copy`, `O_TRUNC` on Unix). The same ordering defeats the demotion below: a verification failure at 2f leaves the tarball's old payload, extracted at 2e, in the export. The two steps are one output-ownership decision: a package with `uploaded == true` is owned by step 2f alone. Step 2e's allowlist becomes the included `repoless_cached` packages with `uploaded == false`; nothing under `repoless-packages/` is extracted for an uploaded package, whatever the entry type. Every name on that allowlist is `format!("{name}-{version}-{release}.{arch}.rpm")` over snapshot fields (`session.rs:3192`), which are untrusted, and `tar::Entry::path()` does not clean `..` (only `unpack_in` does; `tar` 0.4.45 `entry.rs:415`), so a crafted `name` such as `../repoless-packages/epel-release` with a matching tar entry would place a regular file at an uploaded package's exact name by another spelling, or with more `..` outside the export tree. For the packages that stay on the allowlist, a `Symlink` or `Link` entry at an allowlisted name is rejected with `RefineError::TarballError` naming the entry (the scanner writes cached RPMs as regular files, so a link there is a crafted tarball, not a cleaned directory); the `unmanaged/` branch keeps its link handling, since unmanaged files can be links. On verification failure the path is excluded entirely: step 2e did not extract it and step 2f writes nothing, so no member exists from either source. **On verification failure the package is demoted, not the export (position 28):** no member, no active `COPY`, the comment `# FIXME: upload the RPM for <name.arch> again in refine; the staged file could not be verified for export` (the name sanitized, `cache_path` never echoed), and `warnings: ["<name.arch>: staged RPM not verified, not exported"]` in the export response for the client to show. A dnf-cache RPM (`repoless_cached` without `uploaded`) is unchanged in mechanism: its `cache_path` is a host path the export does not copy, as today, and its NEVRA basename passes the filename rule or renders the FIXME (above).

**Trust assumptions, stated for the record.** The 127.0.0.1 bind is reachable by every local user and process, not only the browser user; `origin_guard` (`lib.rs:27-52`) blocks a cross-origin browser `POST` and `DELETE` and allows a request with no `Origin` header, so refine assumes a single-user workstation, and on a shared host another local user can upload, delete, and export.
```
# === Security & Access Control ===
# SELinux file contexts (1 custom rule). Labels for image content are computed at
# deploy time from the image's own policy under /etc/selinux, so a rule only needs
# to be in the policy store: no restorecon at build time. Data you restore into
# /var (/var/srv included) keeps the labels it arrived with; run restorecon -R on
# it before starting the services that use it.
# Each rule removes its own key from the local store if present, then adds it, or
# modifies it when the target policy defines the key; the rules end the local
# list in the order the source host held them. A rule whose path the target
# already maps as an equivalence is skipped with a FIXME in the build output,
# because deleting its key would delete that equivalence.
# /srv is a symlink to /var/srv on this base and the policy has no /var/srv alias;
# this makes every /srv rule, stock and custom, apply to the real path. The
# equivalence is added when absent and left alone when identical; a different
# target mapping stops the build with an instruction.
RUN eq="$(semanage fcontext -l -C | awk -v s='/var/srv' '$2 == "=" && $1 == s { print $3 }')"; \
    if [ -z "$eq" ]; then semanage fcontext -a -e '/srv' '/var/srv'; \
    elif [ "$eq" != '/srv' ]; then printf 'FIXME: %s is already equivalent to %s on the target, not %s; delete that equivalence with semanage fcontext -d -e, or exclude this rule, then rebuild\n' '/var/srv' "$eq" '/srv' >&2; exit 1; fi
RUN spec='/srv/www(/.*)?'; \
    eqs="$(semanage fcontext -l -C)" || { printf 'FIXME: could not list the target file contexts before replaying the rule for %s; fix semanage in the base, or exclude this rule, then rebuild\n' "$spec" >&2; exit 1; }; \
    if printf '%s\n' "$eqs" | awk '$2 == "=" { print $1 }' | grep -qxF -- "$spec"; then \
      printf 'FIXME: skipped the file context rule for %s; the target maps that path as an equivalence, which semanage fcontext -d would delete instead of a label; delete it with semanage fcontext -d -e, or exclude this rule, then rebuild\n' "$spec" >&2; \
    else semanage fcontext -d "$spec" 2>/dev/null || true; \
      semanage fcontext -a -t httpd_sys_content_t "$spec" \
      || semanage fcontext -m -t httpd_sys_content_t "$spec"; fi
# 1 custom SELinux port label(s) detected
RUN semanage port -a -t ssh_port_t -p tcp 2222
```

Rendering rules: every `Label`/`Unlabel` rule is the guarded form of § 3.1 rule 1, the `spec=` assignment from the single-quoted spec, the equivalence-subject check with its `printf` FIXME, and the `-d ...; -a ... || -m ...` triple reading `"$spec"`, the `-d` carrying only `-f` and the spec, the `-a` and `-m` carrying identical arguments; `-f <flag>` appears only when `file_type != All`; `-s <user>` when `user != "system_u"`; `-r <level>` when `level` is `Some` and not `s0`; `Unlabel` renders `-t '<<none>>'` inside the same guard; a collected `Equivalence { subject, labeled_like }` renders the inspect-then-branch `RUN` of § 3.1 rule 2 with `'<subject>'` and `'<labeled_like>'` in the places `/var/srv` and `/srv` take above, both operands quoted at every site, the `awk -v`, the `-a -e`, the comparison, and the `printf` arguments alike; when `fcontext_source` is `SemanageList` the `# NOTE:` order caveat of § 3.1 precedes the first rule. The restorecon sentence about restored data is the one addition to the exported instructions the data-migration workflow needs; the README's SELinux paragraph (`readme.rs:228`) carries the same sentence. ### 6.1 The row rule

Every row answers one question with its left edge. A checkbox means **decide**; an `Advisory: <type>` label in the badge cell with an empty left edge means **homework**; nothing at the left edge and no label means **look**. Containers (section header, package group, repo, unmanaged directory) follow the same rule with a tri-state checkbox acting on their effective members. A control is never rendered for an operation the server will refuse (§ 6.3 states the testable invariant).

**Semantic model: coherent list, native controls, roving rows.** Every list container is `role="list"`, every row, leaf or container header, is `role="listitem"`, native controls sit in the tab sequence, and the existing one-row-at-a-time roving focus stays. This replaces the earlier draft's phase 2 `role="grid"` line and the `role="row"`/`gridcell` markup `DecisionItem.tsx:276-425` renders today; that draft would have put `role="grid"` on containers whose rows stayed `listitem` (`PackageList.tsx:654`) and `group` (`GroupRow.tsx:108`), which is not a grid, and said nothing about how a user reaches a row's child controls. The rows are not tabular: the badge cell count varies per row, the expanded body (`<pre>`, `PackageDetail`, a member list) is not a cell, and a grid reserves ArrowLeft/ArrowRight for cell movement, which § 6.3 binds to collapse and expand on containers (`UnmanagedFileList.tsx:196-204`). Three of the four row kinds are already `listitem` (`PackageList.tsx:654`, `GroupRow.tsx:174` for members, `ContextItem.tsx:19`) and their checkboxes are already tabbable, so Tab and Space habits survive. What the choice costs: a `listitem` cannot carry `aria-checked` or `aria-expanded`, so row state reaches the screen reader through `aria-describedby` text (below) rather than a native state; a long list keeps one tab stop per checkbox, which is today's behaviour; `DecisionItem` changes `role="row"` to `role="listitem"`, drops `aria-rowindex`, and its `role="gridcell"` divs become plain divs with the same class names, in phase 1 as a role-only change (tests querying `getByRole("row")` change with it). **The conversion is one tree in one release.** Every live container and row that carries `row`, `rowgroup`, `grid`, `gridcell`, `columnheader`, or a misplaced `group` today converts in phase 1 (the table below), because phase 1 ships alone and a `list` that owns a `grid` or a `rowgroup` is not the hierarchy this paragraph chooses: WAI-ARIA 1.2 requires a `rowgroup` to be owned by a `grid`, `table`, or `treegrid`, and a `list` to own only `listitem`s. **Focus identity across refetch, collapse, and filter.** `DecisionList.tsx:518-523` resets `focusedIndex` to 0 whenever `flatItemIds` changes; stable React keys alone do not repair that, and it is the bug the earlier draft's "focus stays on the row" claim rested on. Rules:

- A refetch that keeps the id changes nothing: rows are keyed by stable ids (`item.id`, `name.arch`, `group.name`, `repo-header:<section_id>` as `DecisionList.tsx:623` already does), the list never remounts on a view or sections change (`MainContent.tsx:740` `key={lookupId}` stays), so DOM focus stays on the same element with no programmatic move.
- When the id leaves the array (collapse of its container, filter, exclusion into a collapsed zone, ungroup): if the removed element contained `document.activeElement`, focus moves to the nearest surviving predecessor in the previous array; if none, the nearest surviving successor; if the array is empty, the section's `SectionSearch` input (`data-testid="section-search-input"`) or the section heading. A container that collapses is itself a row, so collapsing with focus inside lands on the header. Nothing is announced; the row's own label announces.
- A row that becomes `tabIndex={-1}` while focused (the user moved focus elsewhere) keeps `focusedId`, so Shift+Tab back into the list returns to it.

### 6.7 Server-error toast

The three error paths of item 1.11 become one. App's `onMutationError` (`App.tsx:216-223`) takes `(err: Error, rowName: string)`, is also the value of the `MainContent` prop (`:719-721`, which today only logs), and replaces `DecisionList.tsx:308-357` `handleError` and its `AlertGroup` (`:578-593`). The row name: `MainContent`'s direct `applyOp` callers (`:255-364`) pass the name they hold; `useMutation` (`hooks/useMutation.ts:15-18`) passes the failed op as a second `onError` argument and App labels it from `item_id.key`; `useMutation.ts:41-45` keeps clearing its queue on failure.

**The optimistic flip is an overlay.** `pendingOverride: Map<itemKey, boolean>` is held by the mutation owner (App for the `useMutation` callers, `MainContent` for its direct `applyOp` callers) and a row renders `override ?? confirmed`; nothing is ever written into the view or sections cache before the server answers. The earlier draft enqueued the toast inside `fetchView().then(...)`, so that the row never showed the refused state under a toast; the cost was that when the refine server is unreachable the mutation and the recovery both fail and the user sees nothing, which is the one case `DecisionList.tsx:328-351` guards today (its toast is independent of the refetch and tolerates the refetch failing). The overlay removes the ordering problem that forced that choice. Sequence for any refused mutation, in this order:

1. **Rollback, synchronously on rejection.** The overlay entry is cleared; the row re-renders from the last confirmed cache; `isPending` clears for that row.
2. **Alert, same tick, unconditional.** The `role="alert"` toast below is enqueued in the rejection handler itself, never inside a `.then` on a refetch, and does not wait on anything. Focus does not move.
3. **Recovery, as a separate attempt.** `Promise.allSettled([fetchView(), fetchSections()])`, both because a Configuration Files toggle mirrors into Kernel & Boot; `useView.invalidate` (`hooks/useView.ts:25`) is a counter bump and cannot be awaited, and `fetchView()` itself can reject (`:33-45`), which is why this is `allSettled`. Fulfilled results replace their caches. If either rejects, a second body line is appended to the same toast, `Server state could not be refreshed; what you see may be stale.`, and `staleState: true` renders `state may be stale` as `role="status"` text beside the section title until a later fetch of that endpoint fulfils. Recovery failing never suppresses or delays step 2. The 409 stale-generation branch (`DecisionList.tsx:310-325`) moves here: the same recovery runs and no alert is shown.

**Refused `ContextItem` mutation**, whose state lives in the sections: Space on a sysctl row → overlay set, checkbox shows the new state → `/api/op` 422 → overlay cleared, checkbox shows the sections' `decision.include` → alert with the server's `error` → recovery fetches both endpoints; the row re-renders from the fresh sections with the same value, and if the sections fetch fails the stale line appears.

Content: PatternFly `Alert variant="danger"` with `role="alert"` (PatternFly spreads extra props to the root element), title `Change not applied`, body `<row name>: <err.message>`; `ApiError.message` is the server's `error` field verbatim (`types.ts:1067-1077`, `client.ts:17-20`), no client rewording. The error toasts render from `App` in one `AlertGroup isToast` without `isLiveRegion` (the alert role announces), so they do not stack against `MainContent`'s success group (`MainContent.tsx:468-481`); every other toast stays `status`. Close button, no auto-dismiss for errors; a later successful op on the same row dismisses its error toast. Focus never moves to the toast. Network failure (`err` is not an `ApiError`) uses the same toast with body `<row name>: could not reach the refine server`.

### 6.11 Responsive behaviour

The new row content (path titles, stale repo ids, mixed-header count text, attention buttons) has to survive a narrow panel and 400% zoom without hiding the operative target. Below 640 px (`@media (max-width: 639px)`) `__main` is `flex-wrap: wrap` and badge cells move to a second line aligned with the name's left edge, so the control column keeps its width. `__toggle` and `__expand` stay `flex-shrink: 0` on the first line; both are 24 px minimum hit targets (WCAG 2.5.8).

## 9. Out of scope

- Aggregate and fleet UI, beyond the three compatibility changes this spec forces: the `ItemId::KernelModule` removal in `aggregate_handlers.rs`, the `RepoBar` provenance predicate and state text for `disabled`/`stale`, and `RepoBar`'s Switch state and posted direction read from the effective counts with `handleAggregateRepoToggle` posting the direction it is given (§ 3.2, position 29). Aggregate keeps `RepoBar`'s interaction contract otherwise: the same binary Switch, the same bar, the conflict controls, and no tri-state, repo zone, or list conversion. The aggregate merge changes of § 4 are schema maintenance, not UI.
- Reorganizing the sidebar sections into decision and reference surfaces. The item moves this spec already contains stand (§ 2); the broad regroup is a follow-up sections-reorganization spec.
- Computing `non_default_modules` (loaded, not built in or autoloaded by the base, not declared in `modules-load.d`). The dead constant is dropped; a real computation is its own spec.
- The machine-local data advisory from the `/var` ruling (needs `size_estimate` populated by a real measurement, which this spec removes rather than fakes).
- Relocating the container-storage note to Container Workloads, and suppressing `/var` rows owned by packages present in the target base.
- Tier colour removal beyond what phase 1 names (`repoStyles` on package rows); aggregate views keep their vocabulary.
- The 2026-06-29 commandline-repo pre-spec's `repo_alternative` fields and the `dnf repoquery --available` lookup for `Stale` packages. `RepoAttribution::Stale` is where that lookup would attach, and this spec stops at naming the slot.
- `locked_reason` on `ContextDecision`; the badge reads `Locked` until a reason string exists.
- Converting `ServiceSection.tsx:143-312` and `ContainerSection.tsx:138-290` from their self-consistent `grid > row > gridcell` markup to the § 6.1 anatomy, and `LanguagePackageList.tsx:198`'s `aria-expanded` on a `listitem`. They are outside the phase 1 tree (§ 6.1) and convert when those sections adopt the row rule.
- Deduplicating `rpm.gpg_keys` (nine copies of one path on this host); noticed, not part of the bump.
- A booted-host re-validation of the `/srv` equivalence (`matchpathcon` on a deployed system). Host check B1 (§ 8.14) runs the emitted commands against the base image and settles delete-then-add-or-modify, identical and conflicting equivalences, overlap order by `matchpathcon`, the preseeded-key reposition, and the equivalence-subject refusal; what B1 does not settle is label resolution after `bootc install`, which is assumed from A2 and the bootc labeling model. The synthesized line is redundant only when the target already carries an identical `/var/srv` equivalence, which the build-time inspection turns into a no-op; a differing one stops the build.
- Preserving the precedence of a target-local fcontext key the source does not define against a collected key that overlaps it. The replay appends the collected keys last (§ 3.1 rule 1, position 23), so such a key loses; a refusal design that detects the overlap at build time is the recorded reverse. A label-only deletion primitive: `semanage` 3.6 has none, so a collected label whose exact spec the target maps as an equivalence is refused with a FIXME in the build output rather than replayed (position 30), and the Containerfile cannot name the collision in advance because the renderer never sees the target's store.
- `dnf repoquery --queryformat %{reponame}` on hosts whose dnf prints a different tag (dnf 5 keeps `%{reponame}`; a host that prints nothing parseable yields `None` and the package stays repo-less, which is the safe side). A per-repo query (position 16's reverse) is the fallback if a supported host turns up without the tag.
- Comparing RPM versions. `match_kind: version_differs` says the uploaded version is not the host's; whether it is newer is the user's claim until an `rpmvercmp` port exists.
- Skill and CHANGELOG updates. Implementation of phase 0 updates `serde-include-default-ambiguity.md` (it describes patching `include`; `normalize.rs:64` patches `disposition`), `snapshot-schema-versioning.md` (constants), `web-disposition-contract.md` (the `ContextItem` decision path, the DTO retirement, and the `Inventory` bucket caveat once `loaded_modules` and shadowed config entries are inventory), `rpm-repo-name-mismatch.md` (the substring rule is replaced), and `codebase-layout.md` (`rpm_filename.rs`); and adds `[Unreleased]` entries for the Containerfile changes.
