# Visual & Functionality Nits (2026-03-16, retired 2026-11-01)

> **This list is closed, and all but one of its entries describe a user
> interface that no longer exists. Nothing below is maintained.**

## Why it was retired

These nits were written against the **Python implementation's Jinja2
HTML report**. Their own resolution commits, all dated 2026-03-22, touch
`src/yoinkc/templates/report/_editor_js.html.j2`, `_toolbar.html.j2`,
`_packages.html.j2` and `src/yoinkc/renderers/html_report.py`
(`b9c1413`, `6ef98e1`, `b428ac2`, `f530c15`). That tree was removed at
`9ce7284a`, the Go report that replaced it at `059abcd4` on 2026-05-24,
and the current surface is the PatternFly 6 React UI under
`crates/web/ui/`.

Checked against that UI on 2026-11-01:

| Entry | Status |
|---|---|
| 1. Summary Tab Overhaul | Obsolete. There is no tab structure, so there is no Summary tab. |
| 2. Card Minimize Buttons | Obsolete. No card minimize control exists. |
| 3. Editor (5 items) | Obsolete. There is no editor component. |
| 4. Footer / Toolbar, prevalence slider | Obsolete. No slider component exists anywhere in the UI. |
| 5. Navigation / Back Button | **Still true.** |

Entry 5 is the only one that survived two rewrites, and it survived
because nothing has ever addressed it: `crates/web/ui/package.json`
declares no router, and nothing under `src/` touches `popstate` or
`history`. The browser back button still does nothing and there is
still no in-page way back to a previous screen. It is tracked in the
backlog with the rest of the web UI polish work.

## The lesson this one carries

A list of UI nits outlived two complete rewrites of the UI it described,
and nothing in the list could say so. Four of its five entries read as
outstanding work for over five months after the code they named was
deleted. Work is tracked in the backlog now, where an item records what
was measured and when.

## The content is not kept here

Stripped on 2026-11-01, with the tombstone. Keeping 115 lines
describing a deleted interface in the tree invites someone to act on
them; the table above is the whole of what a reader needs, and the
original text is one `git log -p` away, which is what "the history
should stay findable" actually requires.

The surviving entry is tracked in the backlog with the rest of the web
UI polish work.
